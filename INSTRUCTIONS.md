# Инструкции по развертыванию Proxy Generator

Этот документ описывает, как использовать скрипт `deploy.sh` для автоматического развертывания статического сайта Proxy Generator на вашем сервере с использованием Nginx.

## Об инструменте

**Важно:** Proxy Generator — это инструмент, который генерирует текстовые строки в формате `ip:port:login:password`. Эти строки предназначены для использования в программах или системных настройках, которые поддерживают работу через прокси-серверы. Сам по себе этот инструмент **не создает, не настраивает и не запускает реальные прокси-серверы**. Он лишь помогает сгенерировать конфигурационные данные.

## Предварительные требования

1.  **Сервер:** Вам нужен сервер под управлением Debian-подобной операционной системы (например, Ubuntu).
2.  **Sudo-доступ:** Скрипт требует прав `sudo` для установки пакетов и настройки Nginx.
3.  **Базовые знания командной строки:** Понимание основных команд Linux будет полезно.
4.  **Домен или IP-адрес:** Вам понадобится доменное имя или статический IP-адрес, по которому будет доступен сайт.

## Шаги развертывания

1.  **Загрузите репозиторий на сервер:**
    Сначала вам нужно получить файлы репозитория на ваш сервер. Вы можете сделать это, клонировав репозиторий (если у вас установлен `git`):
    ```bash
    git clone <URL_вашего_репозитория>
    cd <имя_папки_репозитория>
    ```
    Или загрузите архив с файлами и распакуйте его на сервере.

2.  **Сделайте скрипт исполняемым:**
    Перейдите в директорию с файлами репозитория и выполните команду:
    ```bash
    chmod +x deploy.sh
    ```

3.  **Запустите скрипт развертывания:**
    Запустите скрипт с правами `sudo`:
    ```bash
    sudo ./deploy.sh
    ```

4.  **Следуйте инструкциям скрипта:**
    *   Скрипт сначала обновит списки пакетов и проверит, установлен ли Nginx. Если Nginx не установлен, скрипт предложит его установить.
    *   **Путь для развертывания:** Вас попросят указать путь, куда будут скопированы файлы сайта. По умолчанию это `/var/www/proxy_generator`. Вы можете нажать Enter, чтобы использовать путь по умолчанию, или ввести свой.
    *   **Имя сервера (домен или IP):** Введите доменное имя (например, `myproxygen.example.com`) или IP-адрес вашего сервера, по которому сайт будет доступен.
    *   **Порт для прослушивания:** Укажите порт, на котором Nginx будет ожидать подключения. По умолчанию это `80`. Если порт `80` занят или вы хотите использовать другой, введите его.

5.  **Проверка конфигурации Nginx:**
    Скрипт автоматически создаст конфигурационный файл для Nginx и попытается проверить его корректность (`nginx -t`). Если будут обнаружены ошибки, скрипт сообщит об этом.

6.  **Перезапуск Nginx и настройка брандмауэра:**
    После успешного завершения работы скрипта вам будут даны инструкции:
    *   **Перезапустить Nginx:**
        ```bash
        sudo systemctl restart nginx
        ```
    *   **Настроить брандмауэр:** Если у вас активен брандмауэр (например, `ufw`), убедитесь, что он разрешает входящие соединения на выбранный вами порт. Например, для порта 80:
        ```bash
        sudo ufw allow <выбранный_порт>/tcp
        # Например: sudo ufw allow 80/tcp
        sudo ufw reload # Если ufw был неактивен, возможно, потребуется sudo ufw enable
        ```

7.  **Доступ к сайту:**
    Откройте веб-браузер и перейдите по адресу, который вы указали как имя сервера (и порт, если он отличается от 80).
    Например: `http://your_server_name` или `http://your_server_name:your_port`.

## Устранение неполадок

*   **Ошибки Nginx:** Если `nginx -t` показывает ошибки, проверьте созданный конфигурационный файл. Путь к нему будет указан скриптом (обычно в `/etc/nginx/sites-available/`). Распространенные проблемы: опечатки в имени сервера, неправильный путь к файлам сайта, или порт уже занят другим приложением.
*   **Файлы не скопированы:** Убедитесь, что скрипт `deploy.sh` и папка `site/` находятся в одной директории (в корне репозитория) при запуске скрипта.
*   **Сайт не открывается:**
    *   Проверьте, запущен ли Nginx: `sudo systemctl status nginx`.
    *   Проверьте правила брандмауэра.
    *   Убедитесь, что доменное имя (если используется) правильно указывает на IP-адрес вашего сервера (проверьте DNS-записи).
    *   Проверьте логи Nginx (обычно в `/var/log/nginx/error.log` и `/var/log/nginx/access.log`, или специфичные для сайта логи, если они были настроены).

## Удаление (откат)

Если вам нужно удалить сайт:

1.  **Отключите сайт в Nginx:**
    ```bash
    sudo rm /etc/nginx/sites-enabled/<имя_конфига_сайта>
    # Имя конфига сайта обычно совпадает с последним компонентом пути развертывания,
    # например, proxy_generator, если путь был /var/www/proxy_generator
    sudo systemctl restart nginx
    ```
2.  **Удалите конфигурационный файл Nginx (опционально):**
    ```bash
    sudo rm /etc/nginx/sites-available/<имя_конфига_сайта>
    ```
3.  **Удалите файлы сайта:**
    ```bash
    sudo rm -rf <путь_развертывания>
    # Например: sudo rm -rf /var/www/proxy_generator
    ```
4.  Если Nginx был установлен только для этого сайта и больше не нужен, вы можете его удалить (будьте осторожны, если он используется другими сайтами):
    ```bash
    sudo systemctl stop nginx
    sudo apt remove nginx nginx-common nginx-core
    sudo apt autoremove
    ```

Удачи!
